# Agent Note: 保存 Web 启动 URL

Status: implemented

[English](2026-11-11-web-launch-url-persist.md) | 中文

## 问题

Web 进程生成新的启动 token，并仅打印一次带认证的入口 URL。同一 profile 内的全屏 TUI 可能遮住该行，让运维找不到入口。修改已安装的 JavaScript 能暂时恢复可发现性，但下次升级就会失效。

## 决策

现有 Web 运行时插件在就绪时保存带认证的 URL，独立于打印和浏览器交接。经过校验的 `launchUrlFile` 配置接受非空路径或 `false`；省略时解析为 `$DSH_HOME/web-url.txt`，沿用 home 为空或未设置时回退到 `~/.dsh` 的规则。默认值保留运维已有的恢复位置。

原子替换以 `0600` 权限写入 URL 加换行，新建父目录使用 `0700`。已有目录保留原权限。默认凭据副本只在 Harness home 内，不进入工作区或系统临时目录。显式自定义路径时，目录保护责任由运维承担。落盘尽力而为：写入失败的一条诊断不阻止打印、浏览器交接或服务器启动。

## 考虑过的替代方案

**继续修改已安装的 bundle。** 否决，因为升级会悄悄移除恢复能力，实现也没有源码级测试。

**增加独立的落盘插件。** 否决，因为现有 Web 运行时已拥有带认证的 URL 和 Loader 就绪时机。独立插件会重复协调就绪，或者需要仅为复制一个启动值而新增扩展点。该行为保留在现有拥有者中，并通过配置控制。

**仅保留 stdout。** 否决，因为终端备用屏可能遮住唯一打印的凭据。要求主动开启落盘会让现有 profile 继续缺少恢复能力。

## 影响

该文件是凭据，而非普通书签。POSIX 仅所有者可读写的权限无法排除同一操作系统用户、特权读取者、备份或较弱的 Windows ACL。运维必须保护这些位置，或设置 `launchUrlFile: false`。关闭不会删除旧副本。并发进程共用路径时最后写入者获胜；若两个入口都需保留，必须配置不同文件。崩溃或后续启动失败可能留下过期 URL；文件不代表进程仍然存活。此前没有活跃笔记拥有这项落盘决策。
